# 绝对不能碰的合规红线（必背）

> 适用场景：SRC / 补天**已获书面授权**的漏洞挖掘。未获得书面授权的目标一律不测。
> Agent 每轮都会在系统提示词里带上本文的精简版；本页是展开版，可用 `kb_read compliance-redlines` 查阅。

## 一、六条红线（违反任意一条即停止）

1. ❌ **禁止测试企业内网、内部 OA、员工办公系统、第三方合作平台**
   只打书面授权范围内、且在 `data/scope.json` 白名单内的资产。白名单之外的域名 / IP / URL，即使是从测绘结果、JS 泄露、报错信息里看到的，也不碰。

2. ❌ **禁止暴力爆破账号、高频端口扫描、DDoS 压测**
   不做影响可用性与业务连续性的行为。端口探测限最小必要范围与并发；禁止用字典爆破登录 / 验证码接口。

3. ❌ **禁止拖库、批量下载用户隐私数据**
   证明「存在」即可，不取数据。确需取证时**只截最小必要截图**（能证明问题的单条 / 单页），不批量拉取、不落盘长期保存、不外传。

4. ❌ **禁止植入后门、修改 / 删除服务器文件、篡改订单、密码等真实业务数据**
   验证写操作只允许「先添加 → 删掉自己刚加的那个对象」，绝不改 / 删他人已有数据；禁止扣款、清库存、改订单状态、重置他人密码。

5. ❌ **禁止社工钓鱼、短信轰炸**
   不发送钓鱼邮件 / 短信、不诱导真实人员操作；不调用短信 / 邮件接口做轰炸或压测。

6. ❌ **禁止横向移动**
   拿到某台主机权限后，不得以此为跳板继续探测内网其他主机 —— 内网资产属于典型的越界范围。

## 二、快要越线时该怎么做

- **改保守做法**：优先用只读、单点、最小化的方式取证（GET / 差分对比 / 单次请求），而不是「工具能做到就做」。
- **停下来问**：若某个方向必须触碰红线才能继续，停止该方向，向用户说明「为什么需要」与「替代方案」，由用户决定。
- **能力不等于授权**：工具有利用能力，不代表允许对你当前的目标使用。

## 三、项目里已实现的机械闸门（红线之外的第二道防线）

- `data/scope.json` 授权白名单：命令行工具 / HTTP 重放器 / py_exec 执行前强制校验，白名单为空一律拒绝执行。
- HTTP 重放器只允许只读方法（GET / HEAD / OPTIONS），写入方法硬禁用。
- 风险分级闸门：L2 漏洞验证需用户确认，L3 权限 / 横向 / 接管需二次确认（含 `py_exec` 代码执行）。
- 全程留痕：每步命令与输出留档，报告只写证据确凿的结论。
